## 二、Windows 桌面端

双击安装包按向导安装，装完直接启动即可 —— **不需要另开后端**。桌面端外壳会：

1. 在 `%APPDATA%\DDL\data\pglite` 建立本地数据库（首次启动自动建表）；
2. 随机挑一个空闲端口启动内嵌服务（不会和别的软件抢 3001）；
3. 等 `/health` 就绪后再打开窗口。

数据、附件、日志都在 `%APPDATA%\DDL\` 下，卸载不会删除，升级/重装不影响数据。  
日志文件：`%APPDATA%\DDL\desktop.log`。

## 三、双端独立使用与同网同步

两端**各有一份完整数据**，断网时互不依赖：

| | 电脑端 | 手机端 |
| --- | --- | --- |
| 数据存放 | Electron 内嵌 PGlite（`%APPDATA%\DDL\data\pglite`） | APK 内 IndexedDB（库名 `ddl-local`） |
| 断网时 | 完整可用（本来就是本地库） | 完整可用：任务、清单、标签、清单分组 |
| 连上同一网络 | 保持独立使用 | 探测到电脑服务可达后自动双向同步 |

**同步枢纽是电脑上的 `start-lan.bat`（`serve:lan`，监听 `0.0.0.0:3001`）。** 桌面端 Electron 自带的内嵌服务只监听 `127.0.0.1`，手机连不上，所以想同步就要额外开着那个黑色窗口；不开就两端各自离线用，功能不受影响。这一点也顺带解决了校园网客户端隔离导致手机连不上电脑的问题 —— 连不上时手机照样能记任务，等回到同一 Wi-Fi 会自动补同步。

### 同步规则

- **范围**：任务、清单、标签、清单分组（含四象限、日历、子任务、重复规则等字段）。习惯打卡、番茄专注、倒数纪念日、信息源、附件、偏好设置等保持「联网时可用」，离线不缓存。
- **冲突**：按 `updatedAt` **最后写入优先**自动合并，无需人工选择；删除用 `deletedAt` 墓碑，不会在另一端复活；清空垃圾桶的彻底删除用 `purgedIds` 物理删除。
- **时机**：App 启动、每 20 秒、网络恢复、页面重新可见、本地写操作后 1.5 秒。每一步都先探测 `/health`，不可达就安静地保持离线。
- **收件箱对齐**：手机完全离线首次启动时会自建一个收件箱；首次同网同步会自动把任务改挂到电脑端已有的收件箱（`is_inbox` 全局唯一），不会撞唯一索引。
- **接口**：`GET /api/sync/pull` 返回核心实体全量快照，`POST /api/sync/push` 逐条做 LWW 判定后写入。全量快照避免两端时钟偏差导致漏同步。

### 设置页

- **「离线使用与同步」**（仅手机端显示）：显示 `离线使用 / 已连上电脑 / 同步中…`、失败原因、上次同步时间，以及「立即同步」按钮。
- **「服务端连接」**：这里的地址现在**只用于同步**，留空也不影响手机本机记任务。需要同步时填 `http://<电脑IP>:3001`。

> 已验证的链路：模拟 Capacitor WebView 且服务不可达时新建任务 → IndexedDB 出现记录、UI 显示「1 项待办」、无错误横幅；把地址改回可达并刷新 → 任务出现在电脑端 `/api/tasks`，本地 dirty 标记清空，反向 pull 也能把电脑端数据带回手机。

## 四、电脑端同步服务的启动与网络排查

### 启动（二选一）

**方式 A：双击脚本（推荐）**

双击项目根目录的 `D:\A\DDL\start-lan.bat`，会弹出一个黑色窗口，保持它开着就行；关掉窗口即停止同步服务。脚本会：

1. 先探测 3001 上已有的服务：若是新版服务就**直接复用**（不再启动第二个进程）；若仍是旧版（`X-Frame-Options: DENY`），会提示先去旧黑窗口按 `Ctrl+C` 正常退出再重新双击。**脚本不会强制结束 node**，因为强杀会损坏 PGlite 数据目录。
2. 等服务就绪后跑一遍 CORS 自检，把 5 种可能的 WebView 来源逐个打预检。
3. 同时托管前端产物，手机浏览器打开根地址就能看到完整界面；复用的分支也会打印检测页地址。
4. **关闭服务请在黑窗口按 `Ctrl+C`**，不要点窗口右上角 ×，也不要用任务管理器结束 node。

**方式 B：终端执行**

在 `D:\A\DDL`（有根目录 `package.json` 的那一层）执行 `npm run serve:lan`。进到 `apps/server` 等子目录会找不到脚本。

启动后窗口打印：

```
========== 启动自检 ==========
  [通过] /health 已响应 (http://127.0.0.1:3001/health)
  [通过] CORS 预检 http://localhost       HTTP 204 allow-origin=http://localhost
  ...
  CORS 合计：5/5 通过
  静态页面：已托管（手机浏览器可直接打开完整界面）
==============================

========== 手机端连接信息 ==========
  http://10.27.240.66:3001   (WLAN)
=====================================
```

**`CORS 合计` 必须是 5/5**，否则说明仍是旧进程：在旧黑窗口按 `Ctrl+C` 正常退出，再重新双击 `start-lan.bat`。

### 只想确认网络通不通

用手机浏览器打开 `http://<脚本打印的 IP>:3001/`（或 `/health`），能看到完整界面 / JSON 就说明同步链路可用；手机浏览器本身也能当客户端用。手机 App 里填同一地址即可。

### 同网但没同步时怎么排查

1. **手机浏览器先测** `http://<IP>:3001/`。打不开就是网络层问题，与 App 无关 —— 见下面三条；重装 APK 没用。
2. **确认服务是新起的**：黑窗口里 `CORS 合计：5/5 通过`，响应头应为 `X-Frame-Options: SAMEORIGIN`。旧进程不会自动加载新接口（含 `/api/sync/*`），先在旧黑窗口按 `Ctrl+C`，再重新双击 `start-lan.bat`（不要强杀）。
3. **确认手机装的是最新版 APK**：设置页有「离线使用与同步」卡片才说明装上了新包。旧版是纯瘦客户端，没有本地库。
4. **看设置页状态卡片**：点「立即同步」会立刻重试并显示原因；显示「离线使用中（…）」表示 `/health` 没通。

网络层常见原因：

1. 手机连了流量、另一个 Wi-Fi 或访客网络。
2. **校园网 / 公共 Wi-Fi 的客户端隔离**：本机 `sdu_net` 是 `Public` 类别，这类网络常禁止无线客户端互访，同网段也连不上。最可靠的解法是电脑开「移动热点」（设置 → 网络和 Internet → 移动热点），手机改连热点，再重新双击 `start-lan.bat` 取新地址（通常 `192.168.137.1`）。
3. 填的是旧网卡 IP，注意用脚本**当前打印**的地址；只填 `10.27.240.66` 会自动补全为 `http://10.27.240.66:3001`。

> 该模式下同一局域网内的设备都能访问接口，仅建议在家庭 / 可信网络使用。局域网模式的 CORS 来源设为 `*`，桌面内嵌服务仍是严格白名单。

## 六、已知限制

- **安装包未签名**：证书需要付费购买，自用可忽略 SmartScreen 提示。
- **静默安装（`/S`）在无交互环境下不生效**，请正常双击安装。
- **首次打包会卡在 `winCodeSign` 解压**：electron-builder 下载的签名工具含 macOS 符号链接，非管理员账户解不开，会重试 4 次后报错（产物往往已生成）。本机已预置解压结果，后续不再复现。
- **离线模式下**：重复任务完成后不会派生下一个实例（联网同步后由服务端规则处理）；提醒与附件不缓存；同步采用整表快照，任务量极大时单次同步耗时会增加。
- **同步依赖电脑端 `start-lan.bat` 常开**：桌面 Electron 的内嵌服务只监听 `127.0.0.1`，不能直接当同步枢纽。
- `apps/desktop/` 下的 `release/`、`dist-win/`、`out-*/` 是历史构建目录，体积较大，可手动删除（已被 .gitignore 排除）。

## 七、已修复的问题

- **删除任务报「服务器内部错误」（2026-11-05）**：前端 `request()` 给所有请求都加了 `Content-Type: application/json`，DELETE 无请求体导致 Fastify 抛 `FST_ERR_CTP_EMPTY_JSON_BODY`(400)，全局错误处理器又误报成 500。已在 `apps/web/src/lib/api.ts` 改为「只有带 body 才设 JSON 头」，并在 `apps/server/src/app.ts` 增加空 JSON body 兼容解析与 Fastify 4xx 正确映射。实测 DELETE 204、任务进垃圾桶、非法 JSON 返回 400、无 500 日志。
- **手机端日历页红条 `Cannot read properties of null (reading 'data')` + 整块日历空白（2026-11-05）**：手机 WebView 离线时 `/api/*` 会回落成 `index.html`(200 + HTML)，`request()` 里的 `(body as { data: T }).data` 对 `null` 取值抛 TypeError；同时月历网格与侧栏迷你日历的日期格完全取自 `/api/lunar/cells`，接口不可达时格子数组为空。已改为：非 JSON/空响应统一转成可识别的 `ApiError(INVALID_RESPONSE, status 0)`、离线时安静降级；日历格子改由 `date-fns` 本地生成，农历只作可选叠加。实测离线时日历仍有 42 个日期格、无红条。

## 九、检测页报错排查与同步枢纽数据保护（本轮，仍未重新打包）

### 1. 「我这个检测怎么报错？」——先看打开方式

检测页是**同源 iframe 真实加载应用**的，必须挂在 DDL 服务下，不能用聊天窗口自动弹出的静态预览页，也不能双击本地 `file://` 打开。两种典型错误：

| 现象 | 根因 | 正确做法 |
| --- | --- | --- |
| 13 个视图全「注意 / HTTP 404」，顶部 `/health 404` | 打开的是静态预览地址（例如 `127.0.0.1:5xxxx/static-html/.../diagnostics.html`），那个端口只托管了 HTML，没有后端 | 改用 `http://127.0.0.1:3001/diagnostics.html` |
| 三档预览空白、iframe 读不到 DOM | 3001 上还是旧进程，响应头仍是 `X-Frame-Options: DENY` | 在旧黑窗口按 `Ctrl+C`，再重新双击 `start-lan.bat` |

检测页已加入**打开方式预检 `preflight()`**：先探 `/health`，再用隐藏 iframe 探同源 DOM 可读性；只要打开方式不对，就**跳过 13 个视图检测**，只显示一条带正确地址的红/橙提示，不再刷满假失败。错误打开方式下顶部会显示「— 未检测（先修正打开方式）」。

当前正确地址：

- 电脑：`http://127.0.0.1:3001/diagnostics.html`
- 手机 / 平板（同一 Wi-Fi）：`http://10.27.240.66:3001/diagnostics.html`（IP 以黑窗口打印的为准）
- 现在 3001 已是新版：`/health` 返回 `{"status":"ok"...}`，响应头 `x-frame-options: SAMEORIGIN`、`.html` 为 `no-cache, must-revalidate`，启动自检 `CORS 合计：5/5 通过`，检测页实测 **13 通过 / 0 注意 / 0 失败**。

### 2. PGlite 数据目录损坏事件（已止血，旧数据未恢复）

排查时强制结束了正在写 PGlite 的 node 进程，重启报 `RuntimeError: Aborted()`（发生在 `new PGlite(config.pgliteDir)` / `waitReady`）。诊断结果：全新空目录 OK，原目录与备份副本都 FAIL → 是**数据目录状态不一致**，不是依赖包坏了。

- 已把损坏目录完整保留在 `apps/server/data/pglite.broken-20261105-1429`，另有备份 `.preview/pglite-backup-20261105-142951`。尝试过删 `postmaster.pid` / `.s.PGSQL.5432.lock.out` / `pg_internal.init` / WAL 段、替换 `pg_control` 等组合（`.preview/pglite-recover*.mjs`），PGlite 仍无法打开；**旧同步枢纽里的数据目前没能恢复**。
- 新建空 `apps/server/data/pglite` 重启服务，自动迁移建表，`/health` 恢复正常。
- 桌面端用的是另一份库（`%APPDATA%\DDL\data\pglite`），`.preview/desktop-db-probe.mjs` 在副本上验证 `DESKTOP_DB_OK=1`，含 2 个清单、1 条任务「周报」，**桌面端数据完好、未受影响**。

### 3. 空同步枢纽保护（重要）

新建的空库会让 `/api/sync/pull` 返回一个「全新空库」快照。而 `sync-engine.ts` 的 `mergeStore()` 会把「服务端快照里不存在的本地非 dirty 行」视为服务端已删除并丢弃 —— 也就是手机端已同步的数据会被空库反向清空。已加保护：

- `isVirginSnapshot(snapshot)`：tasks/tags/listGroups 全空且除 inbox 外没有清单 → 判定为全新空库；
- `markAllLocalDirty()`：在 `alignInbox()` 之后、push 之前，把本地全部核心行标成 `_dirty: true`，让手机端数据回填服务端，而不是被清掉。

`.preview/verify-virgin-guard.mjs` 验证：造 2 个清单 + 2 条无 `_dirty` 的「已同步」任务，reload 触发同步后本地仍保留 2 条、服务端回填 2 条；验证数据已清理，枢纽恢复干净状态。

## 十九、v0.1.8：桌面 App 直接当同步枢纽（手机 / 平板跨网络同步）

### 1）为什么要改

原来桌面 App 的内嵌服务写死 `HOST=127.0.0.1` + 随机端口，手机永远连不上；而 `start-lan.bat` 用的是 `apps/server/data/pglite`，**跟桌面 App 的 `%APPDATA%\DDL\data\pglite` 是两份互不相通的数据库**。于是手机同步到的是另一份数据，用户在 App 里刚记的任务怎么也同步不过去。

现在改成：桌面 App 自己就是枢纽，一份库、一个进程，手机平板直接连它。

### 2）桌面端改动（`apps/desktop/electron/main.cjs`）

- 端口：`pickPort()` 优先用 **3001**（手机端地址不用记随机端口），被占用才退回系统分配。
- 监听：由偏好 `lanAccess` 决定 `0.0.0.0` 还是 `127.0.0.1`，**默认开启**。
- 偏好文件：`userData/desktop-prefs.json`（`{ lanAccess, preferredPort }`）。单独存 JSON 而不是塞进 PGlite，因为主进程要在打开数据库之前就知道该不该监听全网卡。
- 地址枚举：`lanAddresses()` 过滤掉 VMware / VirtualBox / Hyper-V / Docker 等虚拟网卡（否则用户会填错连不上），Tailscale 网卡排最前并单独标注；过滤后为空则退回显示全部。
- CORS 白名单补上 `http://localhost`、`capacitor://localhost` —— 手机 APK 的 WebView 源是 `http://localhost`，不加只会显示笼统的「无法连接」。
- IPC：`ddl:server:info`（端口 / 是否开放 / 地址列表）、`ddl:prefs:get`、`ddl:prefs:set`（返回 `needRestart`）。

### 3）设置页新卡片（`apps/web/src/components/PhoneAccessCard.tsx`）

- 开关「允许手机 / 平板连进来」，改完提示**需要完全退出软件再重新打开**（服务已启动，改监听地址必须重启）。

### 4）`start-lan.bat` 改成共用同一份库

`scripts/serve-lan.mjs` 新增 `sharedPgliteDir()`：按平台算出 Electron 的 `userData/data/pglite`，存在 `PG_VERSION` 才用，并允许 `PGLITE_DIR` 环境变量覆盖。**注意 PGlite 单进程独占，跑这个脚本前必须先完全退出桌面 App**，否则两个进程写同一目录会写坏。

### 5）顺手修掉的既有问题

`SettingsView` 里所有 `isLocalFirst()` 换成新的 `isSyncClient()`（= 真机 App 或 `?localfirst=1`）。因为 `@capacitor/core` 一被静态引入就会挂 `window.Capacitor`，桌面 Electron 里 `isLocalFirst()` 也是 true，导致**桌面端一直显示手机端的文案**：「手机端导出的是完整 JSON 备份」「手机端暂不支持导入」「数据存在 IndexedDB」。

注意 `sync-engine.ts` 的准入判断**仍然是 `isLocalFirst()`**：桌面端的数据本来就是「IndexedDB 为主、靠同步从内嵌 PGlite 拉」，改成 `isSyncClient()` 会让桌面端直接空掉。桌面端的同步状态文案改成「已与本地数据库对齐」。

### 6）两份库的合并

`scripts/merge-libraries.mjs`：直接用 PGlite 打开两个数据目录，按 `updatedAt` 做 LWW（语义与 `/api/sync/push` 一致）。

```bash
node scripts/merge-libraries.mjs --from <源库> --to <目标库> [--dry]
```

- 有 `updated_at` 的表：`on conflict (id) do update ... where excluded.updated_at > target.updated_at`
- 无 `updated_at` 的（`habit_logs`）：存在就不动
- 收件箱 id 两边不同：源库任务改挂到目标库收件箱，源库那条收件箱本身丢弃（否则撞 `lists.is_inbox` 唯一索引）
- `settings` 跳过：那是「这台机器现在的选择」，被老库覆盖会突然改掉界面偏好
- `--dry` 只统计不写；先跑 dry 看两库行数对比再决定

本次实际结果：老库只有 1 个分组 / 1 个信息源 / 8 条候选，**两边都没有任务数据**；合并新增 10 行、0 失败。备份在 `.backup/pglite-A-oldserver-*` 与 `.backup/pglite-B-appdata-*`。

### 7）跨网络（家 / 公司 / 学校）怎么连

代码层面已经够用，剩下的是一次性网络配置：

1. 电脑、手机、平板都装 Tailscale，登录同一账号
2. 电脑打开桌面 App，设置里能看到 `http://100.x.x.x:3001 (Tailscale)`
3. 手机填这个地址，任何网络下都能同步
4. Windows 防火墙放行 3001 入站（Tailscale 网卡常被识别成「公用网络」，只放行私有会连不上）
5. 电脑电源设置「接通电源时从不睡眠」，否则睡眠即断线

**安全**：局域网模式无登录认证且 `CORS_ORIGINS` 放宽，Tailscale 网络内任何设备都能读写。个人设备可接受，但绝不能把 3001 映射到公网。
